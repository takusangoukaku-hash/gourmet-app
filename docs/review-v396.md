# v396 2回目の全体の見直し — 指摘と対応

v395 までで `docs/review-v392.md` の指摘を片付けたあと、コード全体を5つに分けて精読した（データ層と同期／登録・取り込み・外部API／画面の前半・後半／起動・設定・Service Worker・Firebase のルール）。
指摘はそれぞれコードで確かめてから直した。直さなかったものは下の「未対応」に理由と一緒に残す。

## 直したもの
### 同期（cloud.js・store.js）
- **押し上げは変わったものだけ**: 毎回の同期で全件（150店・400記録なら約600件）を書き直していた。数時間で Firestore の無料枠（書き込み 2万件/日）を超え、削除の控えまで書けなくなるおそれがあった。`pullCollection` がクラウドの `updatedAt` を `remoteAt` に控え、`pushAllRecords` は「クラウドに無い／こちらが新しい」ものだけ。プロフィールも変わったときだけ。随時の送信（`applyOneToCloud`）も控えを更新する
- **読み込みは差分**: 30分に1回の全件以外は `updatedAt > 前回 − 10分` だけ読む（時計のずれの余裕）。差分は「書いた端末の時計」で切るので、オフラインで書いて後から届いた別端末の記録を見落とすことがある。そのまま「店の無い記録・記録の無い写真」を掃除すると別端末の記録を全端末から消してしまうので、**掃除は全件を読んだ直後だけ**（`cleanupAfterPull`）。写真の同期でこちらに無い記録の写真が見つかったら次の読み込みを全件に。設定の「店の無い記録を掃除」はログイン中なら先に全件を読み直し（`Cloud.syncFull()`）、読み直せなければ掃除しない
- 送っている途中でアカウントが変わったら、残りを次の人の場所へ書かない（`pending` に作った人の uid）
- 写真の追加がまだ送られていないうちの付け替えは、追加に店・記録を写して1回で送る（id・本体の無いメタがクラウドにでき、別端末の写真の取り込みが止まることがあった）。本体の場所の無いメタは「クラウドにある」と数えない
- 公開投稿: 写真の URL が通信の失敗で取れなかったときは前の写真を消さない（`photoUrl` を書かずに merge）。ルールの長さの上限（ひとこと 2000・店名 200 など）を超える文字は切る（黙って公開されなかった）
- 削除の控えの取り込みは端末にある写真だけ相手にする（控え1件ごとに写真の一覧を全部読んでいた）。控えの書き込みはまとめて（`markDeletedMany`）
- 消えた写真のサムネを書かない。強制再同期も排他（`runExclusive`）に。ログイン時にも前回送れなかった削除を先に送る
- **他人のデータを整える**（`cleanPub`）: 投稿・コメント・通知・プロフィール・フォローの一覧の画像は `data:image` か Firebase Storage の URL だけ（ほかの URL を `<img>` に入れると見た人の IP などが外へ漏れる）。位置・★・縦横比は数に。バックアップから戻すフォロー中の投稿の控えも同じ
- **削除の保留を端末に控える**: 元に戻すの 5 秒の間に閉じる・切り替わる・落とされると、写真の削除が途中で止まったり確定が走らなかったりして戻っていた。`gourmet.pendingDel.v1` に控え、次の起動で確定する（その間も一覧から外す）

### Firebase のルール（`firebase/firestore.rules`。コンソールに貼り付けて公開が必要）
- 公開投稿の更新は「今の持ち主」だけ（以前は他人の投稿の id で上書きできた）。写真は Firebase Storage の URL か空、表示名・ジャンル・住所に長さの上限
- 公開プロフィールを本人が消せるように

### 登録・取り込み・外部API
- 候補を選び直したとき、前の店の住所・駅・県・市が残っていた（候補に住所が無く通信も失敗すると前の店のまま保存）
- 登録済みの店を選んだとき、前の候補から自動で入ったジャンルを外す（候補を選んだときは v393 から外していた）
- 下書きに写真を足すと、下書きの日付・位置が消えていた（写真ごとに解析済みを控え、読み直さない）。写真を続けて足したときの古い解析・指紋を取っている間の記録の切り替えも捨てる
- 位置の無い手入力の店名で、別の町の同じ名前の店（チェーンの別の店舗）に黙って記録していた → 確かめる
- 位置の無い写真でも、撮影日が2時間以内かアプリ内のカメラで撮ったものなら現在地の周辺の店を出す（自動では選ばない。日付の無いスクリーンショットなどでは聞かない）
- 行きたい店から記録するとき、住所とジャンルも入れる。開いている画面を閉じるとき、保存の確認のシートを外すだけにせず取り消しで閉じる（「保存中…」のまま固まっていた）
- 取り込み: 自信なしの AI のジャンルは記録に入れない／記録するときは判定が終わるのを待つ（最大 20 秒）／全部が取り込み済みだったら最初の画面へ戻す／店名を打っている最中に候補の結果で描き直さない／新しい店のジャンルは候補の種類からも推定
- 検索: 中継の状態の確認は最大 1.5 秒しか待たない（中継が落ちていると毎回 6 秒待っていた）、一時的な失敗で「中継のサービスは無い」と決めつけない。候補の統合で短い名前（「珈琲」など）が別の店を飲み込まない（3文字以上で、頭が同じか長い方の半分以上）

### 画面（views.js）
- 店の詳細: 閉じたあとの「元に戻す」・住所から位置を求めている間に別の店を開いた、のどちらでも開き直していた（`isShopOpen`）。フォロー中の記録の読み込み中に開いたときも届いたら描き直す
- お店の記録の全画面で写真を消した・移したあと、お店の記録を閉じる（消した写真が残っていた）
- 地図の店シートの「みんな」を自分だけの評価で出していた（読み込み後の追加の分）。閉じたシートを描かない
- 写真の選択モードが、発見の ‹ ・駅のチップ・並び替えのあとも残っていた
- 発見の一覧: 通信を待っている間に消した写真が戻っていた（自分の写真は通信の後で読む）。別アカウントでのログインで前の人のフォロー中の写真が残っていた
- 30分より古い現在地で「徒歩N分」「近く」「近い順」を出さない。経路の出発地を、待っている間に選んだ駅で上書きしない。行きたい店だけの地図で外す・元に戻すたびに全体へ飛んでいた
- 店×投稿の照合を軽く（距離で先に外す・名前の正規化を覚える）。探すの一覧では いいね・コメントの数を読まない（12件ごとに数十回の読み込み）。写真の無い店に いいね・コメントを出さない
- 重複した店: 名前が同じでも 2km より離れていればチェーン店の別の店舗とみなす
- コメントを送れなかったら打った文を戻す。ユーザー名の無い人のプロフィールを開かない。お知らせのフォロー状態はまとめて読む。引っ張って更新の帯が、OS の取り消しで開いたまま残らない

### 起動・設定・Service Worker
- 更新の帯の「更新」が効かないとき 4 秒で戻して取り直す。自分で頼んでいない切り替え（別のタブなど）は、文字を打っている・シートを開いている間は待つ
- バックアップの復元をまとめて書き出す。緯度・経度の片方だけの位置は捨てる。保存領域が使えない環境でも起動が止まらない。文字の大きさの値の検証
- タイルのキャッシュの間引きが、SW が止まるたびに数え直しになり働いていなかった

## 未対応（理由つき）
- `index.html` の `user-scalable=no`: 地図以外の画面を指で拡大させないため（文字の大きさは設定で変えられる）。iOS は 10 以降この指定を無視して拡大できる
- ~~manifest の maskable アイコン~~ → v397 で `icons/icon-maskable-512.png`（68% の大きさ・白地）を足した
- ~~写真のメタの読み込みも差分にする~~ → v397。`photoCache` に控え、30分に1回の全件以外は `updatedAt` の差分。写真のメタを書くときは必ず `updatedAt` を付ける（v396 以前の端末が上げた写真は次の全件で届く）
- ~~取り込みで打った店名の「似た店」~~ → v397。写真の位置から 150m 以内で一致率 0.8 以上の登録済みの店があればその店に記録（シートは挟まない）
- ~~写真の取り込み中に移した・消した写真が戻る~~ → v397。書く直前に今のメタを読み直し（`Store.photoMeta`）、消した写真は書かない
