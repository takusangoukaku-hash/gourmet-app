# 日程あわせ（yotei/）

友達と予定を立てるとき、広い期間の中から「行ける人が多い日」を探すための小さな Web アプリ。
幹事が期間を決めてリンクを作り、各自がカレンダーアプリのスクショを上げると、日ごとの ○△× が下書きされる。

本番URL: https://takusangoukaku-hash.github.io/gourmet-app/yotei/

## 使い方
1. 予定の名前と期間（92日まで）、決まっていれば人数を入れて「リンクをつくる」→「リンクを送る」で LINE などへ。
2. 受け取った人は「カレンダーのスクショで答える」→ 名前を入れ、月表示のスクショを期間の分だけ選ぶ。
3. 確認の画面で、色ごとに ○／△／× を選ぶ（例: 紫＝締め切りは ○、オレンジ＝実際の予定は ×）。日をタップすれば1日ずつ直せる。「この内容で送る」。
4. 予定の画面に「行ける人が多い日」が並ぶ。「候補を送る」で上位5日を文字で送れる（最後は LINE のアンケートで決める）。

## 見えるもの・見えないもの
- スクショは読み取り（Cloudflare Worker `/calendar` → Claude）にだけ使い、どこにも保存しない。
- 予定の題は読んだ本人の画面の中だけ。共有されるのは 名前 と 日ごとの ○△×・不明 だけ。
- リンク（24 文字の乱数の id）を知っている人は、答えを見られ、他人の答えも直せる（友達どうしで使う前提）。

## 仕組み
- 素の HTML/CSS/JS。ビルドなし。BITEMAP 本体・diet・lab・meimon とはコード・localStorage（`yotei.*`）を分ける。
- 共有の置き場は Firestore の `plans/{id}`（題・期間）と `plans/{id}/answers/{pid}`（名前・days・時刻）。ログインなしで、SDK を読まずに REST を直接呼ぶ。ルールは `firebase/firestore.rules` の末尾。
- 読み取りは `tools/proxy/worker.js` の `/calendar`（既定のモデルは Haiku。日単位の読み取りは上位モデルと差が無かった）。
- `sw.js` は何もキャッシュしない。本体の Service Worker（上の階層のスコープ）にこの画面を扱わせないために置いている。

## バージョン
`js/app.js` の `APP_VERSION`、`sw.js` の `VERSION`、`index.html` の `?v=`（2箇所）を揃える。本体の `APP_VERSION` は変更しない。
