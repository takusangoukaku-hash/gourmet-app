# グルメ記録アプリ（Webプロトタイプ）

「グルメ記録アプリ仕様書 v2」に基づくWebアプリプロトタイプ。
料理の写真を登録するだけで、自分だけのグルメアルバムが自動的に整理・記録される。

## 起動方法

Node.js / Python 不要。PowerShell製の簡易サーバーで動かす。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\server.ps1
```

を実行し、ブラウザで **http://localhost:5959/** を開く。
（Claude Codeのプレビュー機能からは `.claude/launch.json` の `gourmet-app` 設定で起動）

初回はデータが空。一覧タブの「サンプルデータで試す」ボタンでデモデータを投入できる。

## スマホで使う（PWA対応）

アプリはPWA（Progressive Web App）対応済み。ホーム画面に追加すると全画面のアプリとして起動し、オフラインでも記録の閲覧ができる。

### 同じWi-Fi内のスマホからアクセスする

1. **初回のみ**: PCで管理者PowerShellを開き `tools\setup-smartphone.ps1` を実行（ポート開放とファイアウォール設定）
2. `tools\server.ps1` を起動（再起動）すると「Phone URL: http://192.168.x.x:5959/」が表示される
3. スマホ（同じWi-Fi）のブラウザでそのURLを開く

※ LAN経由（http）では閲覧・登録はできるが、ブラウザの制限によりホーム画面インストールとオフライン機能は使えない。

### 完全なアプリ体験（ホーム画面インストール・オフライン）にする

PWAのインストールにはhttpsが必要。`gourmet-app/` フォルダを無料の静的ホスティング
（GitHub Pages / Cloudflare Pages / Netlify など）にアップロードすると、
スマホで開いて「ホーム画面に追加」→ アプリとして起動できるようになる。
データは端末のブラウザ内に保存されるため、ホスティング側には何も保存されない。

- iPhone: Safariで開く → 共有ボタン → 「ホーム画面に追加」
- Android: Chromeで開く → メニュー → 「アプリをインストール」

## Firebaseの設定（クラウド同期に必須）

写真の同期で `storage/unauthorized` エラーが出る場合は、Storageのセキュリティルールが
未設定（またはテストモードの期限切れ）で読み書きが拒否されている。
[Firebaseコンソール](https://console.firebase.google.com/) → 対象プロジェクト →
**Storage → ルール** を以下に書き換えて「公開」する:

```
rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    // 自分のフォルダ(users/自分のUID/…)は本人だけが読み書きできる
    match /users/{uid}/{allPaths=**} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }
  }
}
```

**推奨ルール（v296〜）**: 上記は最小限の設定。写真のサイズ・形式の制限や、投稿・コメント・
フォロー・通知の「なりすまし防止」まで含めた推奨ルールを `firebase/firestore.rules` と
`firebase/storage.rules` に置いている。Firestore Database → ルール、Storage → ルール に
それぞれ貼り付けて公開する（アプリのコードはこのルールで動くように書かれている）。

反映後、アプリのプロフィール → 詳細設定 → 「写真を再同期」を押すと、
端末内の写真のアップロードとクラウドからの復元がまとめて実行される。
（フォロワーに見せる投稿写真は、ルールとは別のトークン付きURLで配信されるため
この設定で問題なく表示される）

## 店舗データの出典（OpenPOI API）
店名検索・周辺検索・入力補完は [OpenPOI API](https://openpoiapi.com/)（Overture Maps と各自治体・厚生労働省の
食品営業許可・届出オープンデータを統合、無料・キー不要・CORS対応）を最優先で使う。利用条件に従い、
OpenPOI 由来の店舗は `dataSource` / `dataLicenses` / `dataAttributions` を記録と一緒に保存し、設定画面に出典と
[出典・ライセンスページ](https://openpoiapi.com/attribution.html)へのリンクを表示している。
Overture 由来のレコードには Foursquare（Apache-2.0）のデータが含まれる。第三者へデータを再配布する場合は
各ライセンスの再配布条件が加わる（アプリ内で表示するだけなら出典表示で足りる）。

## Yahoo!・ホットペッパー・Google の提供方法（検索中継）
これら3つはキーの登録（Google は課金）が必要なため、キーをアプリに埋め込まず、開発者が用意した
Cloudflare Worker（`tools/proxy/`）に Secret として置き、アプリはその Worker を経由して検索する。
Worker は本番サイトの Origin からの呼び出しだけを中継し、Google へ送る項目と回数も Worker 側で固定・制限する。
設定手順は `tools/proxy/README.md`。本番の Worker は `https://bitemap-search.takusangoukaku.workers.dev`（v319〜、`js/api.js` の `SEARCH_PROXY`）。
利用者が⚙️で自分のキーを入れた場合はそちらが優先される。

## 実装済み機能（仕様書v2との対応）

- **登録（§4）**: 写真選択 → EXIF解析（撮影日時・GPS）→ 周辺店舗候補（Overpass API）/ 名前検索（Nominatim）/ 地図タップ指定。登録済み店舗は候補の先頭に表示し、選択すると再訪として記録
- **自動入力（§1.1）**: 住所・都道府県・市区町村（逆ジオコーディング＋ISOコード変換）、最寄駅（Overpass railway=station）
- **AIによる料理ジャンル判定（§5）**: Anthropic APIキーを ⚙️ 設定で登録すると、料理写真をClaude（claude-opus-4-8）が解析し、料理ジャンル・店舗ジャンルを構造化出力で自動判定。確信度が低い場合は空欄にして利用者に選択を促す。キー未設定時はOSMのcuisineタグからの推定にフォールバック
- **データモデル（§2）**: 店舗と訪問記録を分離。訪問回数・平均評価・代表写真は集計値として算出
- **地図（§6)**: 評価別の色分きピン、クラスタリング、ポップアップ（写真・評価・コメント・詳細リンク）、現在地移動、訪問頻度ヒートマップ（§9統計）
- **一覧（§7）**: 分類（駅/都道府県/市区町村/料理ジャンル/評価）× 並び替え（新着/訪問日/訪問回数/評価/店名）
- **検索（§8）**: キーワード＋都道府県＋ジャンル＋評価＋お気に入りの複合絞り込み
- **写真（§9）**: 種別（料理/外観/店内/メニュー）、料理ジャンル別閲覧、長辺1600pxへ圧縮保存、拡大表示
- **評価（§10）**: 訪問ごとに★1〜5、後から編集可能、店舗は平均評価を表示
- **統計（§11相当）**: 総店舗数・総訪問回数・写真枚数・平均評価・年間/月別訪問・ジャンル割合・都道府県別・6種のランキング
- **お気に入り（§12）**: 店舗単位のON/OFF、一覧絞り込み
- **また来た（v303）**: 登録済みの店に、写真なしで今日の来店をワンタップで足す（店舗詳細・地図のお店シート・よく行く店）。評価なし（星0）で保存し、平均評価には入れない。写真も評価もない記録はフィードに出さない
- **よく行く店（v303）**: 来店回数の多い順に10店。上位3店はメダル表示
- **制覇マップ（v303）**: 訪れた都道府県を、行った店の数で5段階に塗り分ける。県ごとの店数・来店回数・行きたい店の達成を一覧にし、タップでその県の店を表示。境界は `data/japan-prefs.json`（国土数値情報 行政区域データ 2025年版〔CC BY 4.0〕を `tools/geo/build_prefs.py` で簡略化）
- **行きたい店の達成度（v303）**: 行きたい店を訪問すると消さずに「達成」（`doneAt`/`doneShopId`/`doneVisitId`）として残し、行けた数/保存した数を表示。その訪問を削除すると未達成に戻る
- **記録カード（v303）**: 店数・来店回数・都道府県・行きたい達成・制覇マップ・よく行く店を 1080×1350 の画像にし、端末の共有シート（X・LINE・写真に保存）へ渡す
- **プロフィールと検索の役割（v315）**: プロフィールは「写真（自分のアルバム）」と「統計」の2つ。写真の上の検索欄で店名・ジャンル・料理・地名・駅・コメントから絞り込み、写真カードの下に訪問回数と前回を出す。条件での絞り込み・並べ替え・お店と写真の切り替えは検索タブに一本化（v314 のプロフィール「お店をさがす」は廃止）
- **写真の並び（v312〜314）**: ホームの投稿・プロフィールの写真（店ごと）・他の人のプロフィールの写真・検索の写真（ジャンル別・写真モード）を Pinterest 風に。写真の縦横比のまま列に詰め（縦/横 0.75〜1.5 に収める）、写真の上に店名と「ジャンル ・ 都道府県」を重ねる。スマホは2列、広い画面は4列前後。ホームのカードは写真の右上に行きたい保存、下に投稿者といいね（距離・ここへ行く・あなた向け評価・コメントは投稿詳細で見る）。検索タブの「お店」一覧は従来の横長カード
- **地図の見た目（v306）**: iPhone の「マップ」を手本にした自前のベクトル地図（OpenFreeMap のタイル・国土地理院の日本語フォント）。道路名や細かな施設を出さず、すっきり見せる
- **地図のピン（v311）**: 平らな一色の涙型（幅19×高さ30px、拡大するほど大きく z15で1.4倍・z18で1.75倍）。頭の印で平均の端数を示す（白丸＝○.0〜○.4・行きたい店、白の半月◐＝○.5〜○.9。v322〜）。色は評価色（★1〜★5）。凡例は評価の色だけ出す
- **住所検索を国土地理院に・引っ張って更新（v363）**: 住所→位置は国土地理院の住所検索（丁目・番地に強い）を先に使う。ホーム・検索・プロフィールで引っ張ると同期と新版の確認と描き直し
- **重複した店の統合・店舗の詳細の訪問を同じ形に・今年のまとめ（v364）**: 設定→データ「重複した店をまとめる」で同じ店の二重登録を見つけて記録と写真を片方へ移す。店舗の詳細の訪問も訪問の一覧と同じ並び（写真→操作行→日付）。統計の「もっと見る」に今年の店数・回数・新しい店・都道府県とベスト3を出し、画像で共有できる
- **削除を別端末にも・登録時の重複の確認・まとめの年の切り替え・店舗の詳細の写真の帯（v365）**: 消した記録はクラウドに控えを残し、別端末でも同じ記録が消える。登録で登録済みの店と同じ店らしいときは「登録済み: ○○」を出し、保存時にも「同じ店／別の店」を確かめる。まとめは ‹ › で年を切り替え。店舗の詳細の先頭に写真の帯を戻した
- **写真の付け替え・削除、月ごとの振り返り、新しい画面の総点検、速さの再計測（v366）**: 投稿詳細の「…」から、見ている写真を別の訪問・別の店へ移す／その写真だけ消す。統計に「N年M月」の店数・回数・新しい店と写真の帯（‹ › で月を切り替え）。v359〜v365 の画面を暗色・幅360で確認。店150・写真300・CPU4倍遅で v357 と比べて遅くなった所が無いことを確認
- **画面が直前に戻る問題の修正・記録の編集をその場で・行きたい店の整理・写真をまとめて選ぶ・絞り込みの数（v367）**: 起動直後の新版への黙った切り替えは何も触っていないときだけ（切り替え後は元のタブへ）。同期の描き直しでプロフィールが「写真」に戻らない。投稿詳細・訪問の一覧・店舗の詳細の「編集」はその場のシート。行きたい店は「行きたい／行けた」の切り替え・並び替え・達成の取り消し。検索の写真を長押しで複数選んで移す／削除。「詳細」に条件の数と「条件を外す」
- **見直しの続き（v393）**: 登録で遅れて届いた結果が別の記録に入る・日またぎで訪問日が前日になる・GPS つきで手入力した店に位置が付かない、を修正。写真の付け替えを端末間で新しい方に合わせる。公開投稿の時刻と消え残り、駅のチップの行き止まり、ユーザー名の変更など
- **写真の同期の差分（v397）**: 写真のメタも差分で読む、取り込み中に移した・消した写真が戻らない、取り込みで打った店名を近くの似た店に合わせる、Android のアイコン（maskable）
- **まとまりの波紋（v398）**: 地図で重なった店の丸から、現在地と同じ波紋が広がる（地図を見ているときだけ動く）
- **暗色の仕上げ（v399）**: 暗色でチェックボックスや日付の選択も暗色に、読み込み中の骨組みが白く光らない、地図の検索欄を開いても虫眼鏡が残る、動きを減らす設定で現在地の波紋を止める
- **読み上げ（v400）**: 印だけのボタンと編集シートの日付に、VoiceOver で読み上げる名前を付けた
- **押しやすさ（v401）**: 小さいボタン（切り替え・並び替え・ジャンルの札・コメントの削除・写真の ✕・編集シートの星など）の押せる範囲を、見た目を変えずに広げた
- **文字の濃さ（v402）**: 灰色の補足の文字・★の絞り込みの金を少し濃く、暗色の「削除」の赤を明るくして読みやすくした
- **写真のメモリ（v403）**: 大きい写真の画像を持ち続けないようにした（全画面で何十枚も送っても重くならない）
- **データを消されにくく（v404）**: 端末の記録・写真をブラウザに自動で消されないよう頼むようにした。設定の「このアプリ」に端末で使っている容量
- **空きが足りないとき（v405）**: 端末の空きが足りず保存できないときのお知らせを日本語で分かる文にそろえた
- **見直し（v406）**: 地図を開いていないときは波紋の処理を止める、広げた押せる範囲がとなりにかからないように、取り込みを空き不足で止めたときの結果の文
- **長い文字（v407）**: 店名・住所などの欄に文字数の上限、URL のような長い英数字が右端で切れずに折り返す
- **入力の途中を残す（v408）**: 記録を入力している途中でほかのアプリへ行き、その間に iPhone がアプリを終わらせても、次に開くと入力の途中から戻る
- **同期の失敗を知らせる（v409）**: つながっているのに同期が続けて失敗したら、見出しの下に「同期できていません ・ 設定で確かめる」
- **検索の表記ゆれ（v410）**: ひらがな・カタカナ・全角半角の違いを気にせず探せる（「らーめん」で「ラーメン」が見つかる）
- **同じ店の見分け（v411）**: 「らーめん大和」と「ラーメン大和」のように ひらがな・カタカナだけ違う店名も、重複の確認・行きたい店との照合で同じ店とみなす
- **駅の表記ゆれ（v412）**: 「渋谷駅」と手で打った「渋谷」を同じ駅として、駅のチップ・駅での絞り込み・検索で扱う
- **都道府県の表記ゆれ（v413）**: 探すの都道府県の絞り込みで「東京」と「東京都」を1つに
- **入力の途中の下書きの見直し（v414）**: 戻したあとも写真の撮影日で記録・元の下書きも保存で消える・やめても下書きに残る。記録の編集で先の日付を選べない、取り込みで時計の狂ったカメラの日付を使わない
- **下書きの書き込みを2段に（v415）**: 入力の途中で裏に回ったとき、先に店名・★・ひとことを残してから写真を書く。写真が書き終わらなくても文字は戻る
- **検索欄の ×（v416）**: 探すの検索欄に語を消すボタン。裏に回ったときの下書きの書き込みは1回だけに
- **地図の検索欄の ×（v417）**: 地図の検索欄にも語を消すボタン
- **取り込み・行きたい店の見直し（v418）**: 同じ写真を2枚選んでも1枚だけ、保存中は一覧を押せない、途中で閉じても「飛ばす」を覚える。2回行った店の最初の記録を消しても行きたい店は達成のまま
- **写真の付け替えを安全に（v419）**: 写真を別の記録・店へ移す・店をまとめるときの書き込みを1回の取引に。同期と重なっても写真が消えない

- **過去の写真のまとめて取り込み（v326）**: 写真アプリから最大100枚を選ぶと、撮った日と場所ごとに訪問候補にまとめ、店名（自分の店→周辺検索の候補→入力）と★を付けるだけで一括記録。取り込み済み・飛ばした写真は次回出ない。料理ジャンルは AI が自動判定（1日200枚まで）
- **ホーム上部の整理（v328）**: v325 で入れた提案の段（近くの行きたい店・しばらく行っていない名店・近くの自分の店・N年前の今ごろ・最近の記録）と「行きたい店を追加」ボタンを廃止。ホームはフォロー中の投稿だけ（記録が無いときの「まずは1皿」案内は残す）
- **AI判定を全員に（v324）**: 写真の料理ジャンル判定を Worker の `/classify` で中継し、利用者がキーを持たなくても使えるように。モデルは Haiku 5.5、1端末1日30枚まで。自分のキーを⚙️に入れた人はそちらを優先
- **削る版（v323）**: 批評を受けて主役を絞った。ホームのカードは写真・店名・投稿者・いいねの4要素（あなた向け評価は3人以上＋一致率が出せる人2人以上のときだけ）。
  「あなた向け評価」に信頼度（十分／参考／データ不足）、一致率に共通店舗数。統計は4タイル＋「もっと見る」。お気に入り♥は廃止（行きたいに一本化）。地図は凡例の「?」でピンの見方、駅名・幹線道路を少し強く
- **★5 の印（v320）**: 自分か味覚一致率70%以上の人が ★5 を付けた店は、ピンの頭が白縁の金の★になる（半月より優先。金色は ★5 の印だけ）
- **★5 ×N人（v318）**: 平均とは別に、自分と味覚一致率70%以上の人のうち ★5 を付けた人数を、ホームのカードと検索タブの一覧に赤い印で出す（自分だけなら「あなたが★5」）。人数が増えて平均が 4 点台になっても最高評価の店を見分けられる
- **検索ヒットの記録（v301・v317）**: 検索でタップした候補が、どの機能・どの情報源で見つかったかを端末に残す。複数の情報源で見つかった店は全部を記録し（`sources`）、設定画面の内訳ではそれぞれに数える。出典（ライセンス）付きのデータを出した情報源は `dataSource` として店に保存する
- **地図のまとまり表示（v303・v321）**: 近い店のまとまりを Leaflet 風の「丸＋淡い輪」で表示し、中に件数を出す。丸と輪の色は中で一番評価の高い店の評価色（★5 の店を含めば赤）
- **エッジケース（§16）**: 位置情報なし写真（主要フローとして検索/地図指定）、閉店管理、利用形態（店内/テイクアウト/デリバリー）、訪問日時の手動修正

## プロトタイプでの簡略化（本番実装との差分）

| 項目 | プロトタイプ | 本番想定（仕様書） |
|---|---|---|
| 料理ジャンルのAI判定 | 実装済み（Claude API・利用者のAPIキーをブラウザに保存して直接呼び出し） | サーバー経由でAPIキーを秘匿して呼び出し |
| データ保存 | ブラウザ内（localStorage/IndexedDB） | クラウド（§12・§14） |
| アカウント・認証（§3） | なし（単一利用者） | Apple/Googleサインイン |
| オフライン同期（§14.1） | ブラウザ内保存のため常にローカル | ローカル→クラウド自動同期 |
| 店舗検索API | Overpass/Nominatim/Photon（無料・キー不要）＋ Google Places（⚙️でキー設定時。OSM未登録の個人店もヒット） | サーバー経由でキーを秘匿 |

※ ブラウザのサイトデータを消去すると記録も消えるので注意。
